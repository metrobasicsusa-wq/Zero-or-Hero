# 开盘狙击的盘前选股（sniper-500 / sniper-1000）

每个交易日开盘前（约 08:40–09:20 ET），Claude 的盘前任务在这里写 `YYYY-MM-DD.json`（美东日期），推送到
`claude/cloud-paper-trading-ivwxqk`，09:30 的交易轮会读它。开盘后不要再改这个文件：它是这个方向的成绩记录。

```json
{
  "date": "2026-10-14",
  "sniper": {                       // 10-22 起每天都填第 1 名；只有没有一只有一周内期权时才写 null
    "symbol": "META",
    "direction": "call",            // "call" 或 "put"
    "catalyst": "一句话：什么新消息、为什么还没反映在价格里",
    "confidence": 0.4
  },
  "candidates": [                   // 用户 10-15：盘前看过的 3–5 只都打分排名，第 1 名就是 sniper
    {"rank": 1, "symbol": "META", "direction": "call", "confidence": 0.4, "why": "一句话"},
    {"rank": 2, "symbol": "NBIS", "direction": "put", "confidence": 0.2, "why": "一句话"}
  ],
  "claude_b_pick": "META call",     // claude-b 当天选的（我们不选同一只）
  "notes": ["盘前看过的其他候选和不选的原因"],
  "generated_at": "2026-10-14T09:05:00-04:00"
}
```

**停止线（用户 10-21 同意）**：sniper-500 / sniper-1000 各自做完 10 次（一次 = 一笔买入，含它的回撤半张）以后，只要这个账本这些已平的单合计是亏的，就不再下单，只由 sniper-plan-500 / -1000 照常演算（config/s500.json `stop_if_losing`，hero/sleeves.py `losing_stop`）。前 3 次：10-15 CRWV 看跌归零、10-19 CLF 看涨、10-21 HPE 看涨都跌了约八成。盘前照常写这个文件：实盘停了，演算和记分卡还要用。

规则（hero/sleeve_rules.py `Sniper`）：09:30 到 10:00 之间，只要股价没有逆着选的方向走，就买最近到期（有当天到期就用当天的；
`sniper` 里写 `"overnight": true` 就买最近不在当天到期的、拿到下一个交易日 15:50，写 `"expiry": "YYYY-MM-DD"` 就买那天或之后最近的一档——
10-23 T 看跌在文字里写了 10-30，规则读不到，买成了当天到期的一分钱合约）、
离现价约为这只股票平时单日波动一半的期权（AAPL 约 0.5%、CRWV 约 3%；最少 0.3%，delta 低于 0.30 就往价内挪，用户 10-15：
固定 0.10 delta 对慢的大盘股是彩票），账本一半的钱；翻倍后从最高价回撤 40% 卖，否则到期日 15:30 卖。

怎么选（用户 10-13：要和 claude-b 不一样，否则两边结果一样没意义）：
- **扫描全市场**（用户 10-13）：每个交易日约 09:01 先跑盘前扫描（research.yml 的 premarket，结果在
  `research/premarket/YYYY-MM-DD.md`）：券商涨跌榜、成交榜和 data/universe.json 里盘前离昨收 2% 以上的股票和它们的新闻。
  从里面找消息分量最大、还没被跳空吃掉的；高波动中盘股和消息的「二线受益股 / 另一边」优先（这是和 claude-b 选大型股错开的地方），
  大型股也可以选，但必须不是 claude-b 当天那只。要有一周内到期的期权。
- **不撞车**：先读 claude-b 当天的 `journal/bias/YYYY-MM-DD.json`（公开仓库 Cao-YMGG/zero-or-hero，只当参考资料），
  它选了哪只，我们当天就不选那只；把它的选择记在 `claude_b_pick`。
- 要有新的、非财报的消息，而且还没被盘前跳空吃掉（中盘股波动大，跳空超过约 6% 通常已经反映）：产品 / 合同 / 监管 / 分析师大幅上调、
  或者某条大消息的二线受益股（例：大厂宣布新数据中心 → 供电、光模块、液冷的小公司；加密政策 → COIN、HOOD、MSTR）。
- 机械规则（数新闻条数、按跳空大小、分析师评级本身）回测都亏（research/2026-10-13-open-catalyst.md、2026-10-13-analyst.md），
  优势只可能来自判断。
- **每天都下第 1 名（用户 10-22 同意：「不要把自己越改越保守了，这个项目本身的目的就是大胆」）**：10-15 到 10-22 七天里有 4 天因为「没把握」写了 null，但记分卡（research/sniper/scorecard.md，23 个候选）显示信心分没有预测作用（低于 0.2 的平均 -0.7%，0.3 以上 -5.0%），空着只是让「做满 10 次」的停止线来得更慢。所以 sniper 每天都填排第 1 的候选，信心分照打；10 次以后合计还亏就按停止线停。

文件里另加一个字段：`"claude_b_pick": "META call"`（或 null / "未找到"），记录对方当天的选择，方便事后对比两边。

**`skipped`（10-20 起，用户 10-19）**：扫描里所有有新闻、看过但没进 candidates 的名字都列进来，收盘一起记分，
这样漏掉的也能量出来（10-19 亚马逊盘前 +2%、有核电项目新闻，被当成「分析师评级」排除，到 10:20 从开盘又涨了约 1.7%）：

```json
"skipped": [
  {"symbol": "AMZN", "direction": "call", "gap": 0.021, "reason": "分析师评级",
   "why_not": "一句话：为什么没选"}
]
```

- `direction` 按跳空方向填（高开 call、低开 put），记分时按这个方向算；没有方向的不记分。
- `reason` 用短标签，方便分组：「分析师评级」「跳空已吃掉」「消息太弱」「财报临近」「claude-b 已选」「没有一周内期权」「其他」。
- 记分卡（research/sniper/scorecard.md）把「进了候选」和「看过没选」放在一起比，并按 reason 分组。

## 信心分和记分卡（用户 10-15：以后按信心分排名）

`confidence` 是盘前的主观把握（0–1），不是算出来的概率，目前也不影响下单（只下第 1 名、账本一半）。为了检验它，
每天把看过的 3–5 只候选都写进 `candidates` 并打分；`python -m hero.research_sniper_score`（research.yml 的 sniper_score）
按每只当天从开盘起朝所选方向走了多少记分（收盘方向对不对、当天有没有顺向 3% 以上——约 0.1 delta 期权能翻倍的位置），
按信心分和排名分组，写到 `research/sniper/scorecard.md`。攒够几十个数据点后，再决定要不要让分数决定下注大小（不再用低分来空仓）。

## 回测出来的加分项（research/2026-10-15-sniper-factors*.md，用户 10-15）

3,395 次开盘跳空里，当天卖出的话没有任何因素能让开盘狙击变成赚钱；唯一两段时间都成立的是：
**开盘突破 20 日高 / 低点，而且跳空是这只股票平时单日波动的 3 倍以上，拿到第二天收盘**（57 次 +53%/笔，2024 +34%、2025–26 +67%；10-16 更正拆股价格，原来写 +60%）。
所以盘前选股时：符合这两条的候选加分，并且优先拿过夜（`sniper` 里写 `"overnight": true`，规则才会选最近不在当天到期的合约）。另外两条较弱、只作参考：连续第 2 天追最差；
逆着大盘走的个股较好。分析师评级、诉讼监管类消息历史上最差。
