# Codex-500 每日研究与改进规程 v1

用户在 2026-10-05 明确要求本项目每天持续改进。本规程承接该要求，适用于独立 500 美元 PAPER 实验。

## 运行与真实状态

- 期望频率：每天 17:30，America/New_York；交易日做盘后复盘，休市日做数据、方法和故障恢复检查。此时间是为任务选择的默认安排，不是用户指定的收益期限。
- **自动研究调度尚未创建。** 当前工具不提供创建定时 Codex 研究会话的能力。本文件、运行提示词和环境 start_skill 都不能自行唤醒模型。
- 现有 GitHub Actions 外部触发观察器继续工作；它只测试、读取账户、保存记录，不会自动阅读新研究、选择实验或改进策略。不能用观察任务成功冒充每日研究完成。
- 有可用的定时 Codex 执行入口后，应使用同一云环境运行 daily-task-prompt.txt，每日一次；应核验首轮真实执行和产物，不能只检查任务已保存。
- 若任务漏跑，下一次运行记录漏跑日期并补查数据；不倒签报告或伪造“当日已知”结论。

## 每轮起点

1. 阅读 2026-10-05-handoff-v1/handoff.md 和上轮已发布报告，确认账户隔离、当前策略版本、未完成问题和证据截止。
2. 检查已有观察工作流的近期运行、失败和最后成功时间。不要触发第二个观察器、接管外部定时器或修改主账户自动化。
3. 用安全的只读接口核验本项目账户身份、净值、现金、持仓、挂单和可用资金；只发布脱敏摘要。若身份异常或读数不完整，当日状态标为阻塞，继续不依赖账户的研究。
4. 分开记录真实 PAPER 券商事件和离线假设成交。资金核算包括每轮新投入、保留残值、当前资产和全部失败轮次；未知现金流不能记作盈利。
5. 从共享仓库最新提交只读检查 exchange/claude/ 新增/修改内容，记录文件版本和证据级别。建议、演练和未完成回测不能升级为已验证策略。

## 每日学习循环

- 更新机会研究所需的数据来源、抓取时间、行情截止、权限和缺口。没有可信行情就记录缺口，不能用语言推测造出买卖信号。
- 维护候选/淘汰/待验证清单及原因；保留所有试验，不能只展示最好结果。
- 每次主要实验事先写明一个问题、有限参数集、比较基线、成本/成交/资金假设和否定条件；尽量只改变一个因素，避免无法解释结果来源。
- 优先完成已登记实验，而不是每天另起一套规则。长实验跨日更新进度与资源，不冒称完成。
- 评估净成本后收益、尾部损失、尝试失败数、总投入、财富、达到目标所需时间和期末尚未结束的尝试。重叠窗口和同一行情下多候选不算独立样本。
- 没有改善证据时可保持策略不变。每日必须有诚实的研究状态记录，不要求每天修改参数或下单。

## 策略变更边界

- 用户目标为每轮 500 美元到 10,000 美元，接受本轮全部损失。归零/确实无力满足交易要求时结束，复盘后以新版本开始下一轮；“没有合格机会”本身不等于需要重置资金。
- 不把旧 40% 研究阈值或 Claude 的低于 50 美元、两倍转阶段等规则当作本用户已确认的规则。
- 盈利后逐步降低风险是研究方向；具体阈值须预先登记并验证，不能根据已看到的最佳路径倒定。
- 候选先离线验证，再做不提交订单的前向演练。每日研究要求本身不把未验证候选自动部署成交易策略，不授权真实资金交易或接管其他账户。
- 本阶段实际下单仍未启用。现有 observer 还要求现金和净值为 500 且零仓位，不能直接当成交易版监控器；实现交易版须单独完成订单意图持久化、重启/超时/部分成交对账与监控调整。
- 每次改动保留版本、前后规则、支持/反对证据、适用范围、验证结果和回退条件。禁止为了追回亏损无规则地加码。

## 每日输出与交流

仅写共享仓库 exchange/codex/s500/ 下独立日期/版本路径；不覆盖主账户日报或本规程的旧版本。建议报告字段：

- 研究日期、美东时间、实际生成时间、数据截止、来源提交。
- 观察器状态、脱敏账户摘要、当前轮次、累计注资、残值、总财富/净损益，无法核对的字段明确标未知。
- 今日读取的新证据、候选/淘汰情况、已登记实验、执行结果和未完成工作。
- 当日决定（保持不变/继续研究/结束失败实验/提出版本变更）、理由和反证。
- 方法/代码/数据版本、所有候选及失败、成本/成交/重开假设、局限、问题及下一步。
- `research_status`、`automation_status`、`execution_status` 分开描述；无新交易就是无新交易，不制造实际 FILL。

每个完成阶段都按用户已有授权发布给 Claude 交流。依据最新远端树非强制提交，检查仅改允许路径，逐文件回读核对；修正用 supersedes 保留旧版。绝不发布密钥、账户 ID、原始订单/活动 ID、私有机器路径或完整原始账户导出。

同一天重跑先核对已有报告和运行状态。不能把一次 GitHub 发布的非强制更新当作跨券商订单幂等性保证；本日常研究流程不提交订单。
