# 云端研究接线独立设计审查

本审查针对已登记的 `s500_prospective_flush_fixed_panel_v1` 之执行方式，不改变登记协议、59 个交易日、6,633 个符号、策略参数、收益口径或原始代码绑定。以下是设计层要求；实际代码、离线测试、GitHub 部署和首次云端运行须分别取得证据，不能用本审查替代。

## 调度与边界

仅新增一个研究工作流。旧连接观察器、外部触发器及主账户自动化均不作为本研究的采集器，也不修改。工作日 UTC 13:03、20:23、21:23、22:33 触发同一入口；由注册日历和实际纽约时间决定本次允许阶段。13:03 在夏令为 09:03 ET、冬令为 08:03 ET，均处于登记盘前窗口；两个盘后时刻覆盖收市后至少 15 分钟，最后一次用于截止后的无行情请求封账和预设复盘。开始排队的时间不能替代真正执行和收到数据的时间。

- 冬令时 13:03 UTC 对应 08:03 ET，仍在已登记的 00:00—09:20 盘前窗口。可以提前封存，不必等到 09 点。
- 2026-11-02 开始的注册交易日采用 EST；不能把 UTC 20:23 当作收盘后。纽约时区换算和注册 `close_utc` 两者应一致。
- 2026-11-27、12-24 收市 13:00 ET；仍按注册的实际收市时间裁剪分钟线，数据接收截止仍为 17:15 ET。固定 20:23 UTC 采集可合法覆盖，无需另一套早收市定时器。
- 盘前所有请求、选池封存必须在实际截止前完成。日终全部页的接收必须在 17:15 ET 前完成；计算可晚于截止，但不能补写早时戳。
- 自动主研究管线在假日、周末、登记前、2027 年及以后不得请求行情。日历永久保留 59 行；漏跑、停止、失败或没有信号都不删日期。
- 工作流到期后即使 GitHub 仍触发入口，也只作过期退出。可由后续维护关闭工作流；这不延长研究窗口。

GitHub Actions schedule 可能延迟或漏跑。部署成功表示已设置触发，并不保证次日 09:20 前完整采集。未来第一天成功须由真实 run、持久封存、完整原始收据与校验结果证明。

## 持久尝试声明与失败处理

每个登记日期、每个采集阶段在第一个行情 GET 前，先向私有状态分支持久创建不可覆盖的 claim。claim 必须绑定协议摘要、执行代码版本、目标日期、阶段和唯一执行所有者。创建冲突表示已经尝试，后续执行不重新采集；响应不确定不能视为已取得所有权。只有经成功响应或可信回读确认自身 claim 后，才允许请求行情。

这是一项不可过期的采集尝试记录，不是到时可重新接管的租约。并发队列只减少竞争，不能代替原子 create-only。相同工作流人工重跑、不同 UTC 时刻重复触发、进程被杀或机器丢失，都不得绕过它。若 claim 存在而没有最终产物，后续封账将该阶段记录为截至审查时刻未能确认完成，保留 claim 和失败原因，不自动以新行情重建。晚间审查只增加带 as-of 时刻的诊断记录，不抢占采集最终结果路径；截止前已收到的数据，其离线分析和归档可以稍后合法完成。

原始响应、请求/接收时间、选池封存、结果摘要与指针应在同一最终提交可达，并检查它们属于同一 claim。上传 blob 本身不表示已发布，提交响应不确定时需回读确认；同一结果路径禁止替换。计算恢复只能使用已归档输入并保留版本及首次接收时戳，不能以恢复为由再次 GET 行情。

冻结协议使用“窗口内首个请求完整的 bundle”。本接线若进一步限制每天每阶段只容许一次完整采集尝试，应作为保守的执行政策记录，不能声称协议本身要求永不恢复。尝试内部已绑定的有限 429/5xx 重试仍计入原始收据与请求预算；不是跨运行重新采样。

## 数据与权限

私有状态分支持久保存原始响应和完整审计链；GitHub Actions 临时工作目录或有到期时间的 artifact 不能是唯一副本。日终只读 `data.alpaca.markets` 行情接口；本入口不读取账户、订单、活动或期权，不产生交易。日志只输出稳定状态码、数量与安全摘要，不打印响应原文、凭据、私有路径或完整敏感标识。

公有交流仓库仅接收 `exchange/codex/` 下经筛选的研究说明和派生结果，永不复制 raw body、账户号、订单号、凭据或私有运行路径。工作流自身不应获得共享仓库写令牌。研究执行身份与主账户保持隔离。

## 有界执行

每阶段限制请求总数、分页、重试、间隔、超时与工作流时限。归档应压缩并在提交前检查单 blob 和总包大小；超限记明确失败，不能只保存部分样本再标完整。09:20/17:15 实际时间检查优先于重试预算。验证当前源文件字节绑定后再构造行情请求；协议或方法变动须另建版本。

## 必须覆盖的离线反例

1. EDT、EST、两个早收市日、假日、登记前和窗口后。
2. 排队到 09:20 后，或某页接收跨过盘前/盘后截止。
3. 完整 claim、结果已存在、两个执行并发创建、写请求超时、claim 存在但进程被杀。
4. 部分分页、401/403、429/5xx 耗尽、坏 JSON、错误日期或符号、错误 source hash。
5. 对同日相同阶段重跑不触发第二次行情请求；封账阶段从不发行情请求。
6. 半日市场分钟范围、原始包和 manifest 绑定、全组/全变体保留、缺数据不填零。
7. 假拟现在时间仅用于注入式离线测试；生产 CLI 使用系统实际 UTC 时钟，不接受人为回拨来恢复主样本。

## 已完成的独立离线检查

最终调度为 UTC 13:03、20:23、21:23、22:33，仅 10—12 月工作日触发；生产入口依登记日历与实际年份门控，到期不采集也不重算。已有 `CLOUD_ENABLED == true` 为总开关，研究专用 `S500_RESEARCH_ENABLED == false` 为可选暂停开关；未设置专用变量时不阻止已获授权的研究执行。

独立日历复算覆盖 59 天。独立 runner 的 25 个反例测试覆盖重复 claim、响应不确定、claim 写入延迟越过截止、失败归档、as-of 未知后合法确认、晚间审查无行情请求、失败归档不晋升收益、checkpoint 同输入不重算/新输入追加版本、到期入口退出及无生产假时钟参数。测试全部使用注入时钟和内存状态，不发行情请求或 GitHub 写入。

审查发现并已由实现方修复三项问题：到期后仍重算；归档失败但已生成的盈利分析可能混入主 checkpoint；checkpoint 去重未能同时读取 checkpoint 命名空间并排除 rehearsal 状态。精确测试证据与代码绑定见 `independent-wire-review.json`。本轮还通读了 analyzer 和 checkpoint 的分母、缺失、按日均值、原成本、全方案及 final-only 2000 次整日 bootstrap 逻辑，在上游源验证契约成立时未发现剩余阻断。

新增手动 `connectivity` 模式是一次固定历史 SPY/SIP 分钟行情权限检查，独立保存在 connectivity 命名空间，不计未来样本，不进入自动定时采集路径。原 `rehearsal` 仍只做合成数据持久化往返、零行情请求。二者成功均不能替代未来首日有效采集和自动触发证据。
