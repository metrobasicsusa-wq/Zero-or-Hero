# 冻结协议必须能区分的反例

以下为设计审查用的合成情形，没有新市场观察、收益或订单。正式实现可据此建立断言；本文件本身不声称断言已经运行。

| 合成情形 | 必须保留的解释/处理 | 会造成错误的处理 |
| --- | --- | --- |
| 请求在事前截止前发出，最后一页在截止后才收到 | 未及时完成事前范围封存，保存请求和收到时间 | 用请求时间代替收到时间并称事前完整 |
| 先前 20 日查询尚有未取完的 page token，选中股票已经有数据 | 整个排名范围未完成，不能证明 top64/hash32 | 只验证选中股票，静默丢弃未知候选 |
| 全部分页已完整返回，一只新上市股票确实只有 19 个先前交易日 | 按冻结规则排除该股票，记录缺少历史；不一定使整日范围失败 | 把真实短历史与整批网络失败当同一种排除 |
| 今天出现的新 IPO 不在冻结的 6,633 符号池里 | 本期主轨不加入，单列固定池范围限制；未来动态池须另立版本 | 收盘后加入赢家，并称原固定池规则完全继承 |
| 目录里 `has_options` 缺失，但股票符合历史价格和流动性规则 | 按已登记范围处理；原历史研究不要求该标记 | 悄悄增加期权标记过滤后仍称规则完全继承 |
| 09:59 bar 的条目时间是 09:59，首次下载是在 17:00 | 其市场区间于 10:00 完成，实际收到在 17:00；历史模型可计算但实时未知 | 宣称 09:59 已知收盘价或 10:00 已收到数据 |
| 两天均有完整采集，但一天没有 SPY 同跌入选，另一天入选后没有 2% 急跌 | 分别保留零入选与 `no_flush`，都不贡献零收益 | 两天直接填 0 并进入有事件日期平均 |
| 范围/分钟都没运行，但当天市场平静 | 状态为未运行，市场是否无信号未知 | 把未运行记为“没有机会” |
| 信号已经找到，参考入场条目或持有期中一条缺失 | 保留信号且收益未知，不能前后替代或补 0 | 删除信号、视为未触发或用最近价格填补 |
| 三只配对控制中一只未来持有期缺条目，第四近的股票完整 | 原控制不换；目标净收益若完整可保留，三配对超额未知 | 用第四只替换缺失者改变基线 |
| 20 个日历交易日已过去，但只有 2 个完整主组收益日 | 检查点照常报告；日期证据不足 | 为凑 20 个信号日推迟检查并称固定时间计划 |
| 一个日期有 100 个事件，另一天只有 1 个 | 日期等权主端点给两天各一半权重；事件等权单独报告 | 把 101 个 case 叫 101 个独立观察日 |
| 第 20 日收益很高，第 40 日较弱，期末为负 | 三个检查结果都保留，正式期末端点使用完整固定窗口 | 只发表第 20 日结果并提前宣称确认 |
| 一个分箱 4 个信号，只有 2 个完整收益且均为正 | 报告信号 4、完整 2、缺失 2；观察胜率是 2/2，极少样本 | 称 4 笔交易全部盈利或稳定 100% 胜率 |
| 主方案胜率 30%，平均盈利大于亏损且均值正 | 保留全部分布与成本/缺失限制；不因低于 40% 自动否决 | 按 40% 门槛淘汰，或反向声称 30% 就证明高赔率有效 |
| 移除最大正收益后均值转负 | 敏感性可报告，主估计继续保留该收益 | 从主估计删除大赢家或据此自动排除策略 |
| 截止后供应商修订一根 bar，使原亏损改为盈利 | 保留原已封存版本，另存修订与受影响 case，单列修订结果 | 用新条目覆盖主版本而不留下历史 |
| 11 月夏令时结束、11 月和 12 月提前收市 | 按官方日历和 America/New_York 计算实际 UTC/退出时刻 | 固定 UTC 开盘时刻或默认每日 390 分钟 |
| 协议已发布，但没有对应采集运行记录 | 未来日期为 planned，过期未采集为 missed/未运行 | 把登记文件当成已启用定时器或已观察结果 |
| 17:30 复盘任务首次运行，当天没有 17:15 前完成的主分钟数据包 | 如实记录错过主采集截止，允许独立后补但不改写主轨状态 | 因为现在能下载历史条目就称当天主采集已按期完成 |
| 未见日期股票模型收益为 +2% | 只报告股票代理结果；期权可成交及资金路径仍未知 | 乘一个杠杆数后称 $500 末日期权获得对应利润 |

本期采用登记时冻结的原 6,633 符号和既有 ETF 标签，每日对全固定池抓取先前 20 个交易日日线，不声称每日重建动态目录。原历史目录包含 active 和 inactive 条目，受当时目录及名称启发式限制；冻结并未消除这些问题。若未来另版选用每日 active/tradable 动态条目，应明确这是目录机制和目标群体的变更。
