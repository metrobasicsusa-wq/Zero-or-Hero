# 未来日期观察的执行边界

这份登记固定了选池、源版本、时间和评估口径。开盘前采集命令已实现并做离线验证，日终来源有元数据验收函数；没有新增定时器，也没有将日终采集、分析或AI研究接入已存在的连接观察工作流。不要把本说明当作自动部署成功。

## 恢复研究文件

使用 Python 3.12 标准库及 `America/New_York` 时区数据，无新增pip依赖。按发布清单还原所有逻辑文件名，并核对原始SHA256；大JSON额外压缩为gzip时，按 `artifact-manifest.json` 的 `transport_compression` 解压。原始就是gzip的文件不要重复处理。

未来运行应使用本版固定 `protocol.json`、`fixed-panel.json` 和全部绑定方法文件；不能在原登记里改参数、替换方法或重写时间。重做登记需要新版本、新起始日期及 `supersedes`/父版本记录。工作文件放在现有checkout之外或其忽略目录，不创建额外worktree、不改变连接观察器或主账户文件。

原始市场响应和包含完整日线的 `source-bundle.json` 留在私有运行目录。发布时只能另取已检查的派生选池、源哈希、统计和失败原因；不要把整份采集目录、凭据、账户信息或原始行情包上传共享仓库。

## 开盘前

只能在目标日纽约时间00:00至09:20执行，且当天必须在已登记59日历中。下面是10月8日的命令形式：

```bash
python capture_prior20.py \
  --date 2026-10-08 \
  --output-dir private-runs/2026-10-08-preopen-01
```

目录必须不存在。程序使用现有 `ALPACA_500_API_KEY` / `ALPACA_500_SECRET_KEY` 绑定，通过继承的代理与TLS给 `data.alpaca.markets` 发只读请求；密钥可能是代理占位值，不能打印、复制或替换。源请求只取先前20日的SIP/raw/1Day，固定6633符号分104批，全部批次/分页完成后才允许排名。未知、重复和当天/未来数据不会悄悄删掉。

程序先检查日期和方法哈希，再读取凭据或构造网络传输。今天不能提前采明天；09:20后不能把事后数据封存成盘前结果。401/403终止，不在未改变配置时重试；临时网络错误可在现有窗口及固定上限内重试。每批最多20页、每页最多3尝试、全部最多330次GET，启动间隔至少0.5秒。

成功时 `capture-manifest.json` 的 `accepted` 为true，同时保存 `selection-seal.json`、完整输入的 `source-bundle.json`、各页原始字节和收取记录。封存含方法、池、输入和内容哈希，用于发现文件变化；这些执行机时间记录不是经过独立签名的历史送达证明。时间、传输或数据结构任一检查失败时，保留原因及已收到的原始文件，不能对半个池继续排名。

首次失败的证据不得删除。不得根据已看到的日线结果换掉输入或不断重采直到选出想要的股票。纯传输故障若在同一窗口重试，保留全部attempt；第一个请求全部完成的有效包作为主版本，之后仅追加修订。一个完整响应缺少某股历史数据是该股排除理由；它和整批请求失败不同。

## 收盘后和复盘

主源的计划收取窗口为当天实际收盘后15分钟至纽约时间17:15。11月27日及12月24日早收市，按13:00收盘计算；其他日按官方日历。资料必须覆盖封存的全部入选股票及强制基准，SIP/raw/1Min，常规时段右端点为收盘前，不混入收盘时刻的新分钟。

本阶段没有部署自动日终采集命令。未来接线需要保留原始页、全部分页完成证据、实际requested_at/received_at和哈希，然后独立核对原始字节，再调用 `protocol_tools.validate_postclose(...)` 检查封存、时间和符号元数据。这个函数返回的接受仅是**元数据门控**，不能替代原始source哈希核验或分钟合法性检查。

经济分析继承已绑定的 `vendor/flush_engine.py`、`vendor/normalize_bars.py`、`vendor/classify_relative.py`、`vendor/prefix_features.py` 与父版本的三股票控制规则，保留所有36组合。元数据、行情与结果全验证前，不得把日期标成分析完成。日终整体执行器还需后续接线及真实日期验证；直接运行旧父研究固定目录的CLI并不能自动处理这份新登记。

首个所有请求完成的源包即使含缺分钟，也必须保留缺失状态。后续修订另存，不替换主版本。检查原始资料和计算可以在17:30甚至更晚进行；关键是资料与盘前封存是否确实按时取得。17:30才首次启动且没有在窗口内采到资料时，记错过；不能靠历史价格后来仍能下载就改成按期观察。

## 记录与评估

`observation-ledger.json` 是登记时的空账本：59日均未到，未来日期已观察数为0，信号和收益都是null。后续状态需另存带父版本哈希的追加记录，保留这份初始账本。漏跑、源失败、无信号、缺收益各自记录；不得用0替代缺失，也不能隐藏失败日期。

11月4日、12月3日、12月31日的17:30是固定评估节点，不意味着这些时间已有云端任务。中期报告固定口径描述，不调门槛或挑最优分箱。期末唯一主端点和bootstrap方法在协议中；不同完整收益日期少于20只是样本不足标签，不证明策略无效，也不允许为了得到好结果自行延期。

现有 `Codex-500 connection rehearsal` 工作流只提供账户连接观察。只有拿到独立的采集运行记录、按时封存证据、原始源校验和结果记录，才可称本前瞻观察执行成功。此处没有账户、订单、资金重置或额外数据订阅操作。
