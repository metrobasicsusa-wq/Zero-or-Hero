# hero 方案（10-23 用户批准「改」，10-23 收盘后推送、10-26 周一生效）

目标回到 docs/sleeves-plan.md 第一段：每轮 $500 / $1,000 赌到 $10,000，归零重来、记轮数。判决只看一个数：**每轮到 20 倍的概率**，换算成**每个 hero 的成本**（轮数 × 起点 ÷ hero 数）；低于 $10,000 才是正期望的 hero 游戏。平均每 $1、胜率、复利都不再是 hero 账本的判决依据（它们是主账户的问题）。依据：research/2026-10-23-hero-game.md（把各研究的逐笔收益按顺序重放成轮，押一半 / 押满各算一遍）。

## 二、改动（都需要批准）

1. **抄底给一周扩成主力**：2 个账本 → 6 个。价外 3% 拿 5 天（现有 $500）、平值拿 5 天、平值 2 倍止盈、价外 3% 2 倍止盈，各 $500 / $1,000。候选只在**期权价差 ≤10%**（买卖价差 ÷ 中间价）的名字里选，不合格就换下一只；hero 率全靠成本 5%，实盘池 100 只里的小票价差 10% 以上时平均就转负。
2. **末日单改押满**（fraction 1.0）：SPY 0.3% 两个、QQQ 两个、TSLA 3 倍两个、SPY 0.5% 例外两个。押一半的末日单在回测里出不了 hero；押满后一轮 2 笔、一年 100 多轮，靠今晚推的「买不起就归零重开」转起来。出场不改（一半 3 倍 + 回撤；「拿到收盘」峰值更高但 hero 不更多）。
3. **转只演算**：NVDA 末日单两个、TSLA 5 倍两个、SPY 昨跌后买涨两个、财报后漂移 5% 版；昨天加的五个末日单演算标的撤掉。
4. **不动**：突破大跳空（没有逐笔数据，按 research/2026-10-15-sniper-factors3 的 20 倍次数留着）、狙击（判断类；今晚起文件可写 overnight / expiry）、跟 c 方向、财报正股、周权、演算对照（第 2 / 3 名、高开回落彩票）、主账户。
5. **记分**：每周六跑 research_hero_game（不用 API）和实盘的同一列：每条规则 轮数 / 到 2 倍 / 到 20 倍 / 归零 / 每轮笔数 / 每个 hero 的成本。实盘 hero 率低于回测一半以上的，先查成交成本，再谈规则。

## 三、代价

- 押满后 0DTE 账本一轮 2 笔、一年 100 多轮，一个 $500 账本一年烧 $50,000 量级。模拟盘无所谓；真钱时只按「每个 hero 的成本」选规则，末日单那一族是 $17,000 起。
- 抄底给一周的 hero 率是 28 只大票、5% 成本下的数；换成 10% 成本，平均每 $1 从 +5% 变 -5%，hero 率估计掉一半以上。所以第 1 条的价差筛选不是可选项。
- 幸存者偏差：回测池都是今天活着的名字，数字偏高；实盘记分会告诉我们偏了多少。

## 四、做了什么（10-23）

- config/s500.json：8 个末日单账本 `fraction: 1.0`；NVDA 两个、TSLA 5 倍两个、昨跌后买涨两个、财报后漂移 5% 版 `stop_entries`（已有持仓照常卖完），各加演算替身 nvda0dte-plan-500 / tsla0dte-5x-plan-500 / spydip-plan-500 / pead-plan-1000；抄底给一周 6 个账本（价外 3% / 平值 × 回撤 / 拿满 5 天 / 2 倍止盈，`exit`），全部 `max_spread: 0.10`；撤掉 IWM / AMD / AMZN / META / MSFT 末日单演算。
- hero/sleeve_rules.py DipWeek：`exit` hold / take2 / trail，`max_spread` 价差超过中间价的 10% 换下一只（记 sleeve_skip）。
- hero/sleeves.py：每轮结束记 `rounds`（怎么结束、峰值、几笔、哪天），轮记分用它。
- hero/research_hero_game.py：回测的轮 + 实盘 / 演算的轮同一张表；research.yml 每周六 11:00 ET 自动跑、提交到 research/。
- 记分只看轮：到 2 倍 / 到 20 倍 / 归零 / 每个 hero 的成本。
